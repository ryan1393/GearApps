# Cutter-body compatibility matrix (packaged base data)

Generated by `npm run report:cutter-body-matrix` from `tools/manufacturing/base-data/data/*.json`.
It is what a **fresh base-data import** configures, not the live database: no Summary Body Size Rule
is configured by an import, so every 26-blade (13-set) Summary is UNRESOLVED and permits no body until
an administrator sets 076 Standard or 105 Special in Admin > Part Summaries. For the live answer use
`GET /api/v1/cutter-config/body-compatibility` or `npm run audit:cutter-blade-rules -- --matrix`.

- **Required blades** are total individual blades; stored values are matched inner/outer sets.
- **HOS** is the Summary-level `part_summaries.hos`; this project has no per-Part-Type HOS or
  Inner/Outer blade-label fields.
- **Permitted body definitions**: every enabled definition of the effective rule's size; hand,
  supplier and blade family are not restricted. For 105 rows the 8th Dana S/N character still decides
  Standard (not `8`) or Special (`8`) per physical body.
- **Evidence**: SUPPORTED = the quantity identifies exactly one rule; CONFIGURED = Body Size Rule set;
  UNRESOLVED = 26 blades fits 076 or 105 Special, or no enabled definition of the size exists (064);
  CONFLICTING = disagreeing quantities or rule.
